# Plan: the remaining waves onto node:test; Jest removed

- **Goal:** `docs/superpowers/2026-11-18-node-test-rest-goal.md` — every test runs on
  `node:test` with `node:assert/strict`; Jest is gone from manifests, configuration and tests.
- **Architecture:** the 601 Jest files move in four waves by the hardest Jest API they reach
  (plain < spies < fake timers < module mocks), after a step zero that adds the shared helpers
  and makes `batchEnvelope.ts` runner-neutral. Each commit adds its files to
  `tools/node-test-files.json`; Jest's ignores follow from it. Module mocks are replaced by
  the approved seams S1–S14 (S15 only if measured). The end state removes Jest and
  lint-staged, replaces the list with a directory walk and one guard, and rewrites tooling,
  workflows and docs.
- **Tech Stack:** Node 22 and 24 (CI matrix), `node:test`, `node:assert/strict`, `node:util`,
  `tsc` (test build `tools/build-node-tests.mjs`, `tsconfig.node-test.json`), the runner
  `tools/run-tests.mjs`, Biome 2.5.15, husky.
- **Spec:** `docs/superpowers/2026-11-18-node-test-rest-spec.md` (§10 decisions binding).

## Global Constraints

- A moved file keeps its path, its `describe`/`it` titles, its test count (spec §3, §8).
- It imports `describe`, `it`, hooks and `mock` from `node:test` under those names, `assert`
  from `node:assert/strict` (spec §3).
- Conversions follow the matcher table §3.1, equality §3.2, tables §3.3, hooks §3.4,
  `setTimeout` removal §3.5, spies §3.6, fake timers §3.7 — no other mapping.
- Equality is never loosened; each tightened `toEqual` and each rewritten negated equality is
  named in its commit (spec §3.2).
- No runner timeout, no `{ timeout }` on a test or hook, no wall-clock bound; a missed fake
  timer fails through `track`/`advanceWithRealTime`, never hangs (spec §3.5, §3.7, §3.8).
- Production: no cast, `any`, `!`, `ts-ignore`, regex, timeout, retry or polling; every seam
  typed by the real module's contract and defaulting to it (spec §7).
- Only seams S1–S14 (S15 only if Task 3's measurement shows it necessary); S16 is not added;
  any other production change goes to the owner first (spec §7, §10).
- Each seam commit carries a test that its default changes nothing, including the
  missing-responsible refusal on every default path (spec §7).
- A supplied fake for a seam is typed by the seam's contract: a real class over a fake
  connection with members replaced by `mock.method`, never a partial object cast to the
  interface (static first).
- Mutation sampling on both the Jest version (before converting) and the node:test version,
  each half of a compound assertion separately, each mutation asserting its own failure words
  (spec §8).
- Count and title parity per moved file (spec §8), checked with `npm run test:parity`.
- A test found to prove nothing is fixed in its moving commit and named (spec §8).
- The unit run reaches no outside service; fake hosts stay `.invalid` (spec §6).
- Small focused commits; after each commit `npm run build`, `npm run lint:check`,
  `npm run test:check` and the unit run stay green.
- Tooling: npm scripts only — no `npx`, `npm exec`, `node_modules/.bin`, `node -e`, `ts-node`
  or `timeout` wrapper. Single files run as `npm test -- <path>`; a bare `npm test` only
  through the CI gate script. No `test:integration`, `test:high`, `test:live-*` without a
  single file path; no live SAP run in this task.
- Lockfiles are regenerated by npm (`npm install`), never hand-edited; afterwards no
  `"link": true` and nothing resolved outside the registry.
- `CLAUDE.md` is never edited by an implementer: where its text names Jest or lint-staged, the
  controller brings the proposed text to the owner (Task 6.5).

## Review Focus

Failure modes no task's ordinary tests exercise, each with the test that now covers it:

1. **Thrown values that are not well-formed Errors** — a primitive, `null`, an object whose
   `message` is a number, an `Error` whose `message` was deleted. `messageOf` must follow
   Jest (`message` only when a string, else `String(value)`), and `assertRejects` must refuse
   a non-`Error` reason. Test: Task 1.2, `assertions.test.ts` cases
   `messageOf reads a non-string message as String(value)` and
   `assertRejects fails on a non-Error reason even when the text matches`.
2. **`assertMatchObject` over non-plain shapes** — a class instance against a plain expected
   object (Jest passes), an inherited key, an expected `{ k: undefined }` against an absent
   `k` (Jest fails), a `Map`/`Set`/typed array expected (by `isDeepStrictEqual`), an array
   against an array-like. Test: Task 1.2 cases `a class instance matches a plain expected
   object`, `an expected undefined key must be present`, `an inherited key counts as
   present`, `a Map expected compares by isDeepStrictEqual`, `an array-like is not an array`.
3. **Re-entrant timers in the async advance** — a timer scheduled from inside a firing timer,
   a `setInterval` across a long advance, a `clearTimeout` from inside a callback, a zero-delay
   timer scheduled during the last step. Order and counts must match Jest's async advance.
   Test: Task 1.3, `fakeTime.test.ts` cases `a timer scheduled by a firing timer fires within
   the same advance when due`, `an interval of 10 fires 3 times over 35`, `a timer cleared by
   another's callback never fires`, `getTimerCount is 0 after the advance that fired all`.
4. **`.each` titles that `util.format` renders differently from Jest** — `%#` (row index),
   `%p` (pretty-format), `%%`, `$a.b` (dotted path), `%s` over an object or array. A title
   changed silently would pass every assertion. Test: Task 1.4, `testParity.test.ts` case
   `a title differing only in a rendered placeholder fails the check`; and Task 2.1's first
   step lists every placeholder in use across the 868 tables, each confirmed through the
   parity check in the commit that first uses it.
5. **The end-state walk's inputs** — a `….test.ts` under `dist/`, `.test-build/`,
   `node_modules/`, `__fixtures__/` or outside every root's `__tests__`; an untracked test
   file; Windows path separators. Test: Task 6.1, `selection.test.ts` cases over a fixture
   repository, one per input, each failing the guard or being left out as stated.

## Per-file procedure (every moving commit of Tasks 2–5)

For each file of the commit, in this order:

1. `npm run test:parity -- record <files>` (still on Jest).
2. Choose the mutations (spec §8): one per §3.1 row and per helper the file uses, one per
   half of each compound assertion; for a fake-timer file also the timing breakage (a bound
   shortened, a timer left uncleared); for a seam file the seam bypassed. Apply each to the
   production behaviour or the expected value, run `npm test -- <file>` on Jest: red, with the
   failure words noted; revert.
3. Convert by §3.1–§3.7; read each `mockReset` and each `not.toEqual` / `not.toContainEqual` /
   negated `isDeepStrictEqual` by hand (§3.2, §3.6).
4. Add the file to `tools/node-test-files.json`.
5. `npm test -- <file>` green; `npm run test:parity -- check <files>` passes.
6. Re-apply each mutation of step 2: red on node:test with its own failure words; revert.
7. A failure that appears only under node:test (an unhandled rejection Jest hid, a real
   `nextTick`, a `deepStrictEqual` key or prototype) is fixed in the test and named; never by
   loosening.

Commit body lists: the files; tightened `toEqual`s; rewritten negations; each `mockReset`
reading; each mutation (file, what was broken, Jest red, node:test red); fixed tests that
proved nothing; title or count differences (none expected). Before each push: the CI gate.
