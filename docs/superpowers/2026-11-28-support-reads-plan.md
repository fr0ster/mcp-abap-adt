# Support reads over ADT — plan

The goal is `2026-11-28-support-reads-goal.md` and the spec is `2026-11-28-support-reads-spec.md`.
This plan breaks the spec into steps. Every behaviour is in the spec, not here; a step
names its spec section.

## How every step runs

- **TDD.** First the failing test the spec names. Then the change that makes it pass. Then
  the repository's own gates (build, `lint:check`, `test:check`, unit tests).
- **Small commits.** One logical change per commit, in English. Each commit message ends with
  the attribution lines.
- **Worktrees.** Work happens in a worktree under the repository's `.worktrees/`. A main
  checkout's branch is never switched.
- **Registry only.** Every dependency comes from the registry.
  - After every install, the lockfile is checked: no `"link": true` but a repository's own
    workspace siblings, and every third-party entry resolved from the registry.
  - A lockfile is only regenerated by npm.
- **No versions.** The plan changes no package's own version. A dependency range moves
  only to a version that is published.
- **Live runs.**
  - Read-only runs on cloud (trial) are allowed, and stop at any `401`.
  - An on-premise run starts only on the owner's go. The controller says when a stage is
    ready for it.
  - Every live log is saved whole.
- **CI and review.**
  - After every push, the PR's CI is checked, and CI's own step list is run locally first.
  - Each stage ends with an external review on its PR, and every finding is fixed there.

## Stage 1 — `@mcp-abap-adt/interfaces-adt` (spec §1)

This stage has its own PR in `mcp-abap-adt-interfaces`. It is released once, together with
the other open tasks that need interfaces-adt, at the controller's call.

1. Add the `accept` option to the two `IApplicationLog` option types. Typecheck first: an
   option object carrying `accept` compiles.
2. Add `src/runtime/IApplicationJob.ts`: `IGetApplicationJobOptions`,
   `IApplicationJobCatalog` and `IApplicationJobTemplate`. The typechecks prove each one is
   implementable and its `analyse` overloads narrow.
3. Add `src/runtime/IAbapKeywordDocumentation.ts`: the three `…Params` types,
   `IKeywordDocumentationOptions` and `IAbapKeywordDocumentation`, with the same
   typechecks.
4. Export every new type from `src/index.ts`. A typecheck imports each one from the
   package entry.
5. Add the three rows to `ADT_TYPES_ONPREM` and `ADT_TYPES_CLOUD`, with their evidence
   cases (§1.2). The existing table typechecks pass.
6. Write `CHANGELOG.md` and `README.md` (§1.3). Confirm the package still holds types and
   constants only.
7. Push and open the PR. CI must be green, then the external review, then the merge.
8. **Release gate** (spec §4.9, for this package):
   - semver ranges only;
   - every range resolves on the registry;
   - the lockfile audit passes;
   - after the controller's release, a clean install from the registry into an empty
     directory.

## Stage 2 — `@mcp-abap-adt/adt-strategies` and `@mcp-abap-adt/adt-clients` (spec §2, §3)

This stage has its own PR in `mcp-abap-adt-clients`. It builds against the interfaces-adt
of Stage 1 only once that is published.

It merges with the other open clients tasks. One adt-clients 49.0.0, with its adt-strategies,
is cut after all of them, at the controller's call.

1. **Take interfaces-adt.** Move the dependency range to the published interfaces-adt in
   both packages and regenerate the lockfile. Run the lockfile audit.
2. **Capture the corpus** (§3.4).
   - A hand-run, GET-only capture script, under the job's temporary directory, captures:
     - the object document and source of one hit per type, per kind;
     - the hit-list, topic and "Not found" pages, per kind;
     - the `500` of a 21-character APLO name, for both reads;
     - the `500` of `version=1`.
   - The script writes each page's link sidecar by its own count of `a href`.
   - Cloud is run here. On premise runs on the owner's go.
   - Sanitise as §3.4 requires: user fields, the external host, `sap-client`. Check every
     case for anything left.
   - Commit the cases, and delete the script.
3. **`utilDiscoveryTemplates`** (§2.1). Tests first, on the three recorded discoveries and
   a malformed answer.
4. **`docuPage`.**
   - Tests first: element-by-element link comparison against the sidecars, and the edge
     fixtures (empty, `#` and relative hrefs; a truncated page; no `html`; no `title`).
   - Then the tokenizer, in plain code with no regex.
5. **`jsonDocument`**, then **`bluesMetadata`**, each test first, with its malformed and
   other-root cases.
6. Export the readings and their types from adt-strategies. Write its `README.md` and
   `CHANGELOG.md`.
7. **The address records** `APPLICATION_LOG`, `APPLICATION_JOB_CATALOG`,
   `APPLICATION_JOB_TEMPLATE` and `KEYWORD_DOCUMENTATION`:
   - `objects.test.ts` cases first;
   - `noHardcodedObjectAddresses.test.ts` then fails on `applicationLog/read.ts`, as
     intended.
8. **Move the application-log members** onto `APPLICATION_LOG`, with `seg()` and the
   `accept` option. Update `ApplicationLog.test.ts` with the name cases of §3.3. The address
   test goes green.
9. **The job members:**
   - `getApplicationJobCatalog`, `getApplicationJobTemplate` and
     `applicationJobDocuments`, unit tests first (§3.3: URL, name cases, parameter set,
     `Accept`, `timeout: 0`, one request, failures through `analyse`);
   - add them to `publicApiSurface.test.ts`.
10. **The keyword-documentation members:** `getKeywordDocumentation` with `query`, `topic`
    and `position`, and `keywordDocumentationDocuments`, with the same unit tests,
    including `''` values sent as empty parameters.
11. **Conformance.** The conformance check holds the three table rows to the recorded
    typestructure.
12. **Live tests** (§3.3):
    - definitions: positive, namespaced, absent, and the 21-character APLO name;
    - keyword documentation: the query, the no-hit query, the topic proven by its own
      selector links, link fidelity, the version matrix, `406`, and the position
      measurement.

    Run them on cloud first, with `npm run test:detached`. Then the controller reports the
    stage ready, and the on-premise run follows on the owner's go. Every failure is fixed
    before the stage goes on.
13. **ERRATA** entries (§3.3), each with its exact case and its evidence, the corpus cases
    named.
14. **Docs:** `README.md`, `CHANGELOG.md` and `scripts/address-matrix.ts` (§3.5). Run
    `check:docs`.
15. Push and open the PR. CI must be green, then the external review, then the merge.
16. **Release gate** (§4.9) for adt-strategies and adt-clients:
    - the ranges and lockfile audit;
    - adt-strategies is published before adt-clients;
    - after the controller cuts 49.0.0, a clean install of each from the registry into an
      empty directory.

## Stage 3 — `mcp-abap-adt` 24.3.0 (spec §4)

This stage is in PR #404, after the goal, the spec and this plan. It starts only once the
interfaces-adt, adt-strategies and adt-clients of Stages 1 and 2 are visible on the
registry.

1. **Take the dependencies.** Move the ranges to the published versions and regenerate the
   lockfile. Run the lockfile audit and `npm audit --audit-level=moderate`. The existing
   suite stays green.
2. **The refusal codes** `support_read_not_eligible` and `support_read_not_served`, with
   their fixed words (§4.5, §4.6). Unit test first.
3. **The eligibility table** (`src/lib/supportReads/eligibility.ts`), each row naming its
   live test. The equality test against `available_in` and the compact enums comes first,
   and goes green as the tools land.
4. **`served.ts`**, tests first:
   - kept, shared, reset, fail-closed;
   - the three recorded discoveries, basis-740 included;
   - the request counts of every row of the §4.5 table.
5. **`GetApplicationJobCatalog`**, end to end:
   - schema, handler, metadata read in `metadataReads.ts`, `DetailTable` for both parts
     with the as-sent fallback;
   - registration in `ReadOnlyHandlersGroup` and `READ_DEFINITIONS`.

   Unit and wire tests first (§4.7): the name cases, the parameter set, `Accept`,
   `timeout: 0`, the request counts, failures at every level, and the unreadable success.
6. **`GetApplicationJobTemplate`**, the same way.
7. **`GetApplicationLogDefinition`**, the same way, plus the 21-character APLO `500` at every

8. **`GetAbapKeywordDocumentation`**:

   - the `DetailTable` with every link at every level, and the as-sent fallback;

   Tests first, the wire tests included.
9. **The long read.** Add `GetAbapKeywordDocumentation` to `LONG_TOOLS` and
   `tools/long-handlers.json`. The tests: the equality test, a `run_handle`, the background
   answer equal to the in-call answer, and the no-limits tests on the 184 KB page.
10. **The no-limits source test:** no timer or deadline in `src/lib/supportReads/` and the
    four handlers.
11. **Compact `HandlerGet`:**
    - the three types in `CompactObjectType`, `COMPACT_OBJECT_TYPES`, `compactMatrix.ts`
      and `adtProjections.ts`;
    - the name properties and the per-type takes map in `compactSchemas.ts`;
    - the routes in `compactReadRoutes.ts` and the checks in `compactGetRefusals.ts`.

    Routing tests first: both parts, another part refused by name, names unchanged.

15. **Batch and tool sets:**
    - `tools/batch-handlers.json` and the batch test;
    - the `-ro` sets carry every entry;
    - the tool counts;
    - `toolDescriptionsCarryNoLiterals.test.ts` stays green.

    - definitions, documentation and compact, in soft mode;
    - each in-call and in the background.

    Run them on cloud first, then the controller reports the stage ready, and the

17. **Docs** (§4.8):

19. **Before the tag** (§4.9):

    - `npm run test:install`;
