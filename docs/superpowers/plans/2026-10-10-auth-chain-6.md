# The server on the 6.0.0 auth chain — implementation plan

> **For agentic workers: REQUIRED SUB-SKILL: superpowers:subagent-driven-development**

**Goal.** `mcp-abap-adt` stands on the published auth chain (auth-broker 5, auth-providers 6,
auth-stores 5, connection 15, interfaces-auth 7.5, auth-errors 2.2), split by transport into
`@mcp-abap-adt/core` (stdio), the new `@mcp-abap-adt/http` (Streamable HTTP, header credentials
only), the new `@mcp-abap-adt/sse` (HTTP+SSE, header credentials per connection) and
`@mcp-abap-adt/lib` (tools, embeddable server, the helpers both HTTP transports share, no broker, no
stores), with compact one package per transport (`compact`, `compact-http`, `compact-sse`), and
every package released as 18.0.0 from PR #287 — with each request's cancellation reaching every
wait and every send, and every chain failure reaching the MCP client in the chain's own facts and
words.

**Architecture.** lib keeps the tools and a `ConnectionSource` contract each package fills: core
fills it from its default destination through one `AuthBroker`, http from the request's `x-sap-*`
headers, sse from the headers of the request that opens each SSE connection (both through lib's
`headerSource`), the embedder with its injected connection. Streamable HTTP keeps main's instance
pool (routing by `state_handle`, held state, the idle bound) as it is, its instances under the same
rules as any. An SSE connection that closes has its instance closed after its tools settled. A per-request `AbortSignal` lives in lib's
request signal scope; `createAdtClient` hands adt-clients a function reading it at each send, and
connection 15 honours it at every send boundary — releases run outside it. Failures are read once,
structurally, through auth-errors (`failureOf`), and end the tool call before any handler converts
them.

**Spec.** [`docs/superpowers/specs/2026-10-09-auth-chain-6-design.md`](../specs/2026-10-09-auth-chain-6-design.md)
(approved 2026-10-10, §18), answering the goal
[`docs/superpowers/2026-10-09-auth-chain-6-goal.md`](../2026-10-09-auth-chain-6-goal.md).

## Global Constraints

- Nine packages at **18.0.0**, from PR #287, one major (D29).
- Packages: `@mcp-abap-adt/lib` (`.`), `@mcp-abap-adt/core` (`server/`, bin `mcp-abap-adt`, **stdio only**), `@mcp-abap-adt/http` (`http/`, bin `mcp-abap-adt-http`, **Streamable HTTP only**), `@mcp-abap-adt/sse` (`sse/`, bin `mcp-abap-adt-sse`, **HTTP+SSE only**), `@mcp-abap-adt/compact-readonly`, `compact-modify` (as today), `@mcp-abap-adt/compact` (`compact/`, bin `mcp-abap-adt-compact`, stdio, on core), `@mcp-abap-adt/compact-http` (`compact-http/`, bin `mcp-abap-adt-compact-http`, on http), `@mcp-abap-adt/compact-sse` (`compact-sse/`, bin `mcp-abap-adt-compact-sse`, on sse) (D35, D37, D48, D49).
- SSE stays (D48). Nothing removes it, and no check asserts it is gone.
- The published lib, http, sse, compact-http and compact-sse reach no `@mcp-abap-adt/auth-broker`, `@mcp-abap-adt/auth-stores` or `interfaces-auth-broker`; core is the only package that declares them, compact reaches them only through core; http and sse never reach each other; compact-http and compact-sse never reach core (D38).
- What http and sse share lives in `@mcp-abap-adt/lib/http-transport` (D50): DNS-rebinding protection, the TLS listener, `headerSource`, the TLS rows, the HTTP-transport shutdown sequence (last step: http the pool's shutdown, sse the instance close of each connection). The instance pool is http's alone.
- 18.0.0 ranges: auth-broker `^5.0.1`, or the range of the auth-broker release on auth-stores 5 when C2 finds one published (core), auth-stores `^5.0.0` (core, from A5's third commit, D54), auth-providers `^6.0.1`, connection `^15.0.0`, interfaces-adt-connection `^2.1.0`, interfaces-auth `^7.5.0`, auth-errors `^2.2.0`, interfaces-auth-broker `^1.3.0`, interfaces-auth-sap `^3.3.0`; interfaces-adt and adt-clients: the prerequisite releases of B3 and B5 (§18: the next free minor — today 13.3.0 and 27.1.0) (D1).
- One copy of `interfaces-auth` 7 and of `auth-errors` 2 resolves (`npm ls`).
- Registry only: every range resolves on npm; a prerequisite is published before anything builds against it; no `file:`, `link:`, `workspace:`; the lockfile holds no `"link": true` and nothing not from the registry (H7).
- The HTTP package takes credentials **only** from `x-sap-url`, `x-sap-client`, and `x-sap-jwt-token` or `x-sap-login` + `x-sap-password`, of each request, on a new instance or the pooled one its `state_handle` names; nothing stored, shared or cached across requests, except the connections held state opened, until it ends (D39, spec §3.8). The SSE package takes them the same way from the `GET` that opens each SSE connection; a `POST` is routed by `sessionId` alone; nothing is shared across connections or outlives one (D48).
- An SSE connection that closes runs **the instance close** (D51), built on main's close: the session leaves the routing map (main's) and its instance's latch is set, its tools are aborted, **their settlement is awaited**, then `shutdownState()` (main's), then its MCP server and transport are closed, awaited; one promise per instance. `BaseMcpServer.dispose()` is main's, **extended**: still callable again (each call retries what the state could not undo), and once nothing is held it closes the connections the instance built, each once.
- **The instance pool is main's and is carried into `@mcp-abap-adt/http` as it is** (D52 amended, spec §3.8): routing by `state_handle`, the lease, kept while holding, disposed when empty, retry, `onEmpty`, the batch `400`, `stop()`'s drain and report, the bearer handle. Pooled instances register in the one registry, are aborted and awaited at shutdown before the pool's own shutdown runs, and leave the pool only through `dispose()`.
- **Held state's idle bound**: `--state-idle-minutes` / `MCP_STATE_IDLE_MINUTES` / YAML `state-idle-minutes` (30–35 791, default 30) — the project owner's one exception to "no timeouts" — is one shared lib row in every binary's table, unchanged. `--exposition`'s `debug` (compact: beside `ro` / `rw`), `x-sap-debug-terminal-id` / `x-sap-debug-ide-id` (http, sse) and `SAP_DEBUG_TERMINAL_ID` / `SAP_DEBUG_IDE_ID` (core: the destination's `.env`; every binary: the environment) keep main's meaning.
- HTTP and SSE `400` without credentials, verbatim: "this server takes credentials only from the request's headers: send x-sap-url with x-sap-jwt-token, or with x-sap-login and x-sap-password".
- HTTP and SSE `400` on `x-mcp-destination`, verbatim: "destinations are served only by mcp-abap-adt (stdio); send x-sap-* headers".
- `--transport` is removed entirely; each of the six bins is flag-free about its transport; any value stops the start with the binary's D39 sentence (§10.1).
- `--login-timeout=<seconds>` (`MCP_LOGIN_TIMEOUT`, YAML `login-timeout`), whole number 1 to 86 400, **no default**; fired → "The login was ended by the server's login timeout (`--login-timeout=<n>`)" (D10).
- `--shutdown-timeout=<seconds>` (`MCP_SHUTDOWN_TIMEOUT`, YAML `shutdown-timeout`), **no default**; no shutdown deadline, no drain timer (D33).
- `--renewal=refresh-then-login|refresh-only` (`MCP_RENEWAL`, YAML `renewal`), default `refreshThenLogin()`; under `refresh-only`: "Logins are off (`--renewal=refresh-only`): log in with `mcp-auth`, or start without it." (D11).
- `onWriteFailure`: `'continue'` for a named destination (with or without `--unsafe`), `'fail'` for the `--env` / `--env-path` file; no `--session-write-failure` (D12).
- `--auth-debug` (YAML `auth-debug`), **no environment form**, core only (D24).
- `--browser` enum `system` (default) / `auto` / `chrome` / `edge` / `firefox` / `none` / `headless`, mapped by `process.platform` per §8; `--browser-program` excludes `--browser`; `--browser-auth-port` default **61001** (D9).
- The aborted request's code is connection's `ADT_REQUEST_ERROR.ABORTED` = `'ADT_REQUEST_ABORTED'`, answered `request_aborted` in fixed words (D34).
- A tool failure is JSON `{ error, kind, message, hint, server? }`: chain failure → `authentication_failed`; `DestinationConfigError` → `destination_refused`; aborted → `request_aborted`; own refusals `destination_refused` / `fresh_connection_unavailable` / `inspection_only` / `credentials_required` (§7.3).
- Out of every answer: `diagnostics` (stderr only), `facts` beyond `kind`, a thrown value's `message`, a token, a URL with a query, `state` (§7.3).
- A `403` with an ADT exception body is an ADT error, never `authentication_failed` (D47).
- `failureOf` reads no `message`, no `name`, uses no `instanceof` on a chain class (D14).
- Roles (spec §18, 2026-10-11): the session store alone judges its record (auth-stores 5's `record-format`), the provider obtains, renews and presents, the broker composes and judges the binding, the target system or IdP judges the credential; the server judges none and checks no record itself (D54).
- stdio serves `basic`, `snc` and `jwt` / `authorization_code`; `jwt` / `none` is refused naming where it went (D53); a handed-over token is served only from `x-sap-jwt-token` (http, sse). No broker release is a prerequisite: B1 and C1 are withdrawn.
- No regular expression over untrusted input in the touched files (D26, H8).
- Nothing new on stdout; prompts on stderr (§9).
- Releases (unlocks, closes) are sent outside the request's signal (D40).
- No built-in timeout of the server's or the chain's making (H5).
- `freshConnection?: (options: { signal?: AbortSignal }) => Promise<IAbapConnection>`; without it the operation is refused: "This operation needs an ABAP session of its own; the connection was given by the host, which supplied no fresh-connection factory (`freshConnection`)" (D20).
- Publish order (dependency order): `.`, `./compact-readonly`, `./compact-modify`, `./server`, `./http`, `./sse`, `./compact`, `./compact-http`, `./compact-sse`; the publish is the user's (§11, §13).
- Tests: never `npx jest`; `npm test -- <path>` (root — also every compact package's suites, ruling 15), `npm --prefix server test -- <path>`, `npm --prefix http test -- <path>`, `npm --prefix sse test -- <path>`; a break is restored by copying the saved file back — never `git checkout`.
- Work only in `/home/okyslytsia/prj/mcp-abap-adt/.worktrees/auth-chain-6` (server) and a worktree of each prerequisite repository; the main checkouts are shared.

16. **Main's instance pool is carried, not redesigned** (spec §3.8, D52 amended). A5 keeps
    `InstancePool.ts` and the pool's routing in `StreamableHttpServer.ts`, replacing only how a

    unchanged unless a rule of this change requires otherwise — each such change named in its
    task's commit message. The handle's bearer semantics are the user's open question (spec §18).
17. **The debugger's options move with their transports** (spec §10.1): A5's http and sse launchers
    hand `stateIdleMinutes` and `stateLogger` to their servers as core's launcher does on main; A6
    puts `--state-idle-minutes` (lib's shared row, `src/lib/config/stateIdleMinutes.ts`) in every
    binary's table, `SAP_DEBUG_*` in core's help, `x-sap-debug-*` in http's and sse's; nothing about
    them changes for a user but that a destination's `.env` no longer serves http and sse.
18. **The debugger's own clients** (`src/lib/debugger/ports.ts`, built directly, not by
    `createAdtClient`) are sites of C3's list: a debugger tool call's own sends carry its request's

    scope (`runWithoutRequestSignal`, C4), since a function read at send time would find the starting
    call's signal, aborted when that call ended (spec §3.8, §5.2).

## Per commit: what is installed

The repository has no npm workspaces; development and CI install only with the root `npm ci`,
and every package resolves its imports from the root `node_modules` (paths, as today). So the root
manifest decides the tree: a package core or http needs at runtime is in the root manifest —
lib's `dependencies` where lib uses it, else root `devDependencies` — at **the same range** as the
`dependencies` of the package that publishes it. A task that moves a dependency (A3, A5, C2,
C10, C13) changes both manifests in the same commit and runs the clean `npm ci` + gate + packed
install of A5 step 2a.
