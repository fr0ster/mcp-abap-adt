# The server on the 6.0.0 auth chain — implementation plan

> **For agentic workers: REQUIRED SUB-SKILL: superpowers:subagent-driven-development**

**Goal.** `mcp-abap-adt` stands on the published auth chain (auth-broker 5, auth-providers 6,
auth-stores 5, connection 16, interfaces-auth 7.5, auth-errors 2.2), split by transport into
`@mcp-abap-adt/core` (stdio), the new `@mcp-abap-adt/http` (Streamable HTTP, header credentials
only), the new `@mcp-abap-adt/sse` (HTTP+SSE, header credentials per connection) and
`@mcp-abap-adt/lib` (tools, embeddable server, the helpers both HTTP transports share, no broker, no
stores), with compact one package per transport (`compact`, `compact-http`, `compact-sse`), and
every package released as 19.0.0 from PR #287 — with each request's cancellation ending every
wait of the server's and keeping it from a tool not yet started, a started tool running to the end,
every ADT session the server owns closed with a logoff (D55), no signal anywhere in the chain and a cancel
doing nothing to SAP, the low set gone from the full binaries (compact is its analogue), a tool's
session sending only LOCK and UNLOCK stateful, the long tools on the user's
approved list taking an optional `timeout` on their own connection (D56), and every chain failure
reaching the MCP client in the chain's own facts and words.

**Architecture.** lib keeps the tools and a `ConnectionSource` contract each package fills: core
fills it from its default destination through one `AuthBroker`, http from the request's `x-sap-*`
headers, sse from the headers of the request that opens each SSE connection (both through lib's
`headerSource`), the embedder with its injected connection. Streamable HTTP keeps main's instance
pool (routing by `state_handle`, held state, the idle bound) as it is, its instances under the same
rules as any. An SSE connection that closes has its instance closed after its tools settled, its connections
closed with a logoff. A per-request `AbortSignal` lives in lib's request signal scope and ends the
server's own waits and a request whose tool has not started; it does not reach the requests a tool
sends to SAP — a started tool runs to the end, and a lock is released by its session's logoff
(D55); the chain itself has no signal any more (D56). Failures are read once,
structurally, through auth-errors (`failureOf`), and end the tool call before any handler converts
them.

**Spec.** [`docs/superpowers/specs/2026-10-09-auth-chain-6-design.md`](../specs/2026-10-09-auth-chain-6-design.md)
(approved 2026-10-10, §18), answering the goal
[`docs/superpowers/2026-10-09-auth-chain-6-goal.md`](../2026-10-09-auth-chain-6-goal.md).

- Registry only: every range resolves on npm; a prerequisite is published before anything builds against it; no `file:`, `link:`, `workspace:`; the lockfile holds no `"link": true` and nothing not from the registry (H7).
- The HTTP package takes credentials **only** from `x-sap-url`, `x-sap-client`, and `x-sap-jwt-token` or `x-sap-login` + `x-sap-password`, of each request, on a new instance or the pooled one its `state_handle` names; nothing stored, shared or cached across requests, except the connections held state opened, until it ends (D39, spec §3.8). The SSE package takes them the same way from the `GET` that opens each SSE connection; a `POST` is routed by `sessionId` alone; nothing is shared across connections or outlives one (D48).
- An SSE connection that closes runs **the instance close** (D51), built on main's close: the session leaves the routing map (main's) and its instance's latch is set, **its tools' settlement is awaited** (none aborted, D55), then `shutdownState()` (main's, the state undo), then **the terminal close** — its connections closed with a logoff whatever the undo answered (its leftovers reported) — and its MCP server and transport are closed, awaited; one promise per instance. `BaseMcpServer.dispose()` is main's, still callable again (each call retries what the state could not undo) and stays the state undo only; the connections are closed by the terminal close (`closeOwnedConnections(instance)`), which every terminal disposal runs after the undo, **never conditional on the undo succeeding** (spec §6.4).
- **The forced close** (a second `SIGTERM` / `SIGINT`, or `--shutdown-timeout`; spec §6.4): one lib implementation for core, http and sse; awaits no tool, no `settled()` / `settled(instance)`, no instance close already running, no pool drain, no state undo; writes the logoff of every owned connection (the process-wide owned-connection view, each `disconnect()` joined if under way; connection 16 resolves once written — no SAP request aborted); exits `1` naming what was pending. A tool that never settles cannot hold it.
- **The instance pool is main's and is carried into `@mcp-abap-adt/http` as it is** (D52 amended, spec §3.8): routing by `state_handle`, the lease, kept while holding, disposed when empty, retry, `onEmpty`, the batch `400`, `stop()`'s drain and report, the bearer handle. Pooled instances register in the one registry, are awaited at shutdown (not aborted, D55) before the pool's own shutdown runs, and leave the pool only through `dispose()` followed by the terminal close.
- **Held state's idle bound**: `--state-idle-minutes` / `MCP_STATE_IDLE_MINUTES` / YAML `state-idle-minutes` (30–35 791, default 30) — the project owner's one exception to "no timeouts" — is one shared lib row in every binary's table, unchanged. `--exposition`'s `debug` (compact: beside `ro` / `rw`), `x-sap-debug-terminal-id` / `x-sap-debug-ide-id` (http, sse) and `SAP_DEBUG_TERMINAL_ID` / `SAP_DEBUG_IDE_ID` (core: the destination's `.env`; every binary: the environment) keep main's meaning.
- HTTP and SSE `400` without credentials, verbatim: "this server takes credentials only from the request's headers: send x-sap-url with x-sap-jwt-token, or with x-sap-login and x-sap-password".
- HTTP and SSE `400` on `x-mcp-destination`, verbatim: "destinations are served only by mcp-abap-adt (stdio); send x-sap-* headers".
- `--transport` is removed entirely; each of the six bins is flag-free about its transport; any value stops the start with the binary's D39 sentence (§10.1).
- `--login-timeout=<seconds>` (`MCP_LOGIN_TIMEOUT`, YAML `login-timeout`), whole number 1 to 86 400, **no default**; fired → "The login was ended by the server's login timeout (`--login-timeout=<n>`)" (D10).
- `--shutdown-timeout=<seconds>` (`MCP_SHUTDOWN_TIMEOUT`, YAML `shutdown-timeout`), **no default**; no shutdown deadline, no drain timer (D33).
- `--renewal=refresh-then-login|refresh-only` (`MCP_RENEWAL`, YAML `renewal`), default `refreshThenLogin()`; under `refresh-only`: "Logins are off (`--renewal=refresh-only`): log in with `mcp-auth`, or start without it." (D11).
- `onWriteFailure`: `'continue'` for a named destination (with or without `--unsafe`), `'fail'` for the `--env` / `--env-path` file; no `--session-write-failure` (D12).
- `--auth-debug` (YAML `auth-debug`), **no environment form**, core only (D24).
- `--browser` enum `system` (default) / `auto` / `chrome` / `edge` / `firefox` / `none` / `headless`, mapped by `process.platform` per §8; `--browser-program` excludes `--browser`; `--browser-auth-port` default **61001** (D9).
- ~~The aborted request's code `ADT_REQUEST_ABORTED`, answered `request_aborted` (D34)~~ — withdrawn by D56: connection 16 has no such code; C2 removes what A4 built for it.
- A tool failure is JSON `{ error, kind, message, hint, server? }`: chain failure → `authentication_failed`; `DestinationConfigError` → `destination_refused`; own refusals `destination_refused` / `fresh_connection_unavailable` / `inspection_only` / `credentials_required` (§7.3).
- Out of every answer: `diagnostics` (stderr only), `facts` beyond `kind`, a thrown value's `message`, a token, a URL with a query, `state` (§7.3).
- A `403` with an ADT exception body is an ADT error, never `authentication_failed` (D47).
- `failureOf` reads no `message`, no `name`, uses no `instanceof` on a chain class (D14).
- Roles (spec §18, 2026-10-11): the session store alone judges its record (auth-stores 5's `record-format`), the provider obtains, renews and presents, the broker composes and judges the binding, the target system or IdP judges the credential; the server judges none and checks no record itself (D54).
- stdio serves `basic`, `snc` and `jwt` / `authorization_code`; `jwt` / `none` is refused naming where it went (D53); a handed-over token is served only from `x-sap-jwt-token` (http, sse). No broker release is a prerequisite: B1 and C1 are withdrawn.
- No regular expression over untrusted input in the touched files (D26, H8).
- Nothing new on stdout; prompts on stderr (§9).
- **D55**: a request's signal ends the server's own waits and a request whose tool has not started (D5, D32); it reaches no request a tool sends to SAP — a started tool runs to the end and answers. Every connection the server creates or takes over ends with `disconnect()` (the logoff, which releases the session's SAP locks) on every path; an injected connection is the consumer's to close. D40 and `runWithoutRequestSignal` are withdrawn.
- **D56**: the per-request signal is removed from the whole chain (B6–B9); the MCP SDK's `extra.signal` has one remaining use — the server's own waits that send nothing to SAP (browser login, `connect()`, the provider build) and "a request cancelled before its tool starts never reaches it" (A8). A cancel does nothing to SAP: no logoff, no reopen while the instance lives; a logoff only at an instance's end (pool eviction, idle bound, stop tool, SSE close, stdin end, shutdown) and at the end of a connection made for one operation; a reopen only when SAP already lost the session. No `IAdtError.refusal`: an auth failure inside a tool reaches the model with the connection's own message, as it is.
- **D56**: the low set leaves `mcp-abap-adt`, `mcp-abap-adt-http`, `mcp-abap-adt-sse` (`fullToolSet`); `--exposition=…,low` stops the start: "the low set is gone from mcp-abap-adt / -http / -sse; use mcp-abap-adt-compact (or -compact-http / -compact-sse)"; no gap-filling in high / readonly; a low → compact mapping table, checked against the code; a low capability compact lacks is a finding for the user. Compact keeps `HandlerLock` / `HandlerUnlock` / `HandlerUpdate`.
- **D56**: only LOCK and UNLOCK are sent stateful; everything else runs stateless. The debugger's debuggee sessions are the debugger's session.
- **D56**: long tools named in the list take an optional `timeout` (no default; the one written exception to the no-timeouts rule); each runs on its own stateless connection; a timeout or the end closes that connection with the logoff; no timer left pending. The list is explicit, decided tool by tool by the user — not a category (GET, read-only, stateless: a stateless `POST` may write); C16 drafts the candidates from the code and **the user approves the list before any code**; no tool gets the timeout without being on it; activation and the debugger are not on it unless the user puts them there. The description advises a timeout below the client's request limit (TS SDK: 60 s); a cancel does nothing to SAP.
- **19.0.0's scope, as the user states it**: the major; the low set removed (compact is its analogue); a guaranteed logoff on every connector close; the timeout for listed long tools; the auth stack update; the per-transport package split (A0–A7).
- No built-in timeout of the server's or the chain's making (H5) — except the listed long tools' `timeout`, the one written exception (D56), and the idle bound.
- `freshConnection?: () => Promise<IAbapConnection>` (no signal, D56; A9 built it with `{ signal }`, C2 removes it); without it the operation is refused: "This operation needs an ABAP session of its own; the connection was given by the host, which supplied no fresh-connection factory (`freshConnection`)" (D20).
- Publish order (dependency order): `.`, `./compact-readonly`, `./compact-modify`, `./server`, `./http`, `./sse`, `./compact`, `./compact-http`, `./compact-sse`; the publish is the user's (§11, §13).
- Tests: never `npx jest`; `npm test -- <path>` (root — also every compact package's suites, ruling 15), `npm --prefix server test -- <path>`, `npm --prefix http test -- <path>`, `npm --prefix sse test -- <path>`; a break is restored by copying the saved file back — never `git checkout`.

### Task C24 — `@mcp-abap-adt/responsible-rules`

**Why (the owner, 2026-10-14).** The rules that name the responsible, the user and the system are the server's, not
the library's: "Ці правила на сервері тобто вбудовувач взагалі без правил" — "В іншу винести просто" — "Ця проблема
взагалі для http/sse існує тому шо на stdio все одразу прописується. А от http/sse можуть коннектитись до різних
систем. І тут оті правила визначення відповідального і нужні." Name: `@mcp-abap-adt/responsible-rules`.

**The rules (unchanged; the owner's recipe of C15 rounds 39–42, quoted verbatim in the C15 briefs):** a destination is
the credentials + the ABAP system; `systeminformation` with the information wins; without it — cloud one step to the
error (a 404: the configuration / headers are inconsistent; anything else: the ABAP system's problem), on-premise two
steps (the stated responsible, else the login; neither: the error); a 401 as it came, never replaced; the on-premise
404 kept per destination; the system kind required.

**What stays in lib (the mechanism, no rule):** the `systeminformation` reader (its three answers: information, 404,
anything else), the per-destination store, the main flow, the instance close and its logoffs, the
`systemContextResolver` hook. An embedder (`EmbeddableMcpServer`, `HandlerExporter`, a self-registered registry) gets
no rule by default: no kind required, nothing looked up unless it passes a resolver; what it does with the mechanism
is its own.

Steps:
1. List, with file:line, every place in lib (`src/`) that applies a rule above (the kind requirement, the recipe, the
   lookup before a tool, the stdio-start checks) and say for each: rule → moves, or mechanism → stays. Show the list
   to the user before moving anything.
2. Create the package `responsible-rules/` beside the others, copying `background-runs-memory/`'s shape whole
   (package.json, tsconfig, build/test/lint scripts, README, the root's build/prebuild/jest mapping, CI lint step,
   release lists, RELEASE.md / GITHUB_ACTIONS.md package counts and publish order). It depends on `@mcp-abap-adt/lib`
   only (same-repo sibling).
3. Move the rules there behind the lib's hook; lib keeps only the mechanism; remove from lib every rule step 1 lists.
4. Wire it: http and sse apply the rules per call; core (stdio) applies them once at its start (exit 1 on failure); the
   compact and -ro binaries get them through their transport's package. Embedders get none unless they pass it.
5. Tests: the rules' own suite in the new package (the cases the C15 rounds 39–42 tests cover, moved, not rewritten);
   lib's tests prove an embedder without the package applies no rule (no kind required, no lookup); the transports'
   tests prove they apply them. Each proven load-bearing.
6. Docs: the new package's README; MIGRATION-19.0 (embedders: no rules by default, how to opt in; the package list);
   ARCHITECTURE; the package counts.
7. Gates as every task; the external review once, its findings to the user.
