# Plan: a contract lives where it is accepted — the ADT client (#216)

**Goal:** [`2026-10-24-client-contract-goal.md`](../2026-10-24-client-contract-goal.md)
**Spec:** [`2026-10-24-client-contract-design.md`](../specs/2026-10-24-client-contract-design.md)

Three repositories, each with its own PR. The order is fixed by the spec (§5): interfaces-adt is
published before adt-clients depends on it, and adt-clients before mcp-abap-adt does.

## Global constraints

- No behaviour change. Every request and every answer stays as it is.
- interfaces-adt receives contracts only: the result-set contracts and `IServiceBindingPublicationConfig`.
  No value, no composition, no client contract.
- A contract is taken from interfaces-adt or composed from its contracts, never from an
  implementation package.
- Dependencies are taken from the registry only. Lockfiles are regenerated by npm. Commands run
  as npm scripts, never `npx`.
- Breakage is found by the compiler: `build`, `test:check` and each repo's CI steps.
- PR #281 (adt-clients 37.4.0, adt-clients-legacy 0.1.0) merges and is released before Task B1.
- adt-clients paths are under `packages/adt-clients/`, the legacy package's under
  `packages/adt-clients-legacy/`. The root's `src` names no legacy class, tests included.

## Review focus

1. **Default result sets.** A consumer that called a factory without a result set gets the
   class's own default (`typeof xDocuments`), with slots exactly as narrow as today. Pinned by
   a type-level assertion per object kind group (Task B3).
2. **Legacy factories.** `AdtClientLegacy` keeps assignable overrides after the compositions go,
   including the eleven getters re-declared with two overloads (Task B3b).
3. **The shape check stays a guard.** After the switch to classes, it still refuses a factory that
   claims an atom its class does not offer. Proven by breaking one claim (Task B4).
4. **Consumer substitution.** A contract composed from interfaces-adt alone accepts `AdtClient`
   and a hand-written object (Task B5) and `AdtClientLegacy` (Task B3b). It also refuses an object that lacks a
   member the contract names, proven by a negative type check.
5. **`resultsFor(…)` in mcp-abap-adt.** The server's own result sets flow through its contract with
   the same inference as through the class today (Task C2).

## Part A: interfaces-adt (fr0ster/mcp-abap-adt-interfaces, `packages/interfaces-adt`, 20.2.0)

### Task A1: the result-set contracts and the publication config

Done: interfaces-adt 20.2.0 is published (the registry's `latest`).

- Each of the 30 `IXResults` (35 factories; `IClassResults` serves six) is added to its object's `src/adt/IAdtX.ts`, copied from adt-clients'
  `core/<dir>/types.ts`.
  - The names and slots stay as they are, all `readonly …: IResultStrategy<unknown>`.
  - `IMessageClassMessageResults` keeps its generics and their defaults.
  - `IClassResults` is declared once.
- `IServiceBindingPublicationConfig` is added to `IAdtServiceBinding.ts`, as it is.
- Each new export is added to `src/index.ts` and to `tools/package-map.json`.
- A type check under `src/__typechecks__/` composes a two-factory client contract from this
  package's atoms and result-set contracts alone, and a hand-written object satisfies it.
- Verify: the repo's build, typecheck, `check-surface`, `check-graph` and `check-packed` pass.
- README and CHANGELOG get a 20.2.0 entry, a minor.
- Commit, open the PR, and run the Codex review. The owner merges and publishes.

## Part B: adt-clients 38.0.0 and adt-clients-legacy 0.2.0 (this repository)

### Task B1: rebase and the dependency

- Rebase onto main after #281 is merged and released.
- Measure spec §1 again on main and correct it where it differs.
- `@mcp-abap-adt/interfaces-adt` moves to `^20.2.0` in `packages/adt-clients`, installed from the
  registry; the root lockfile is regenerated by npm.
- Check the lockfile: no link but the workspace siblings.
- Verify: build and unit suite green before any type moves.

### Task B2: the result-set contracts come from interfaces-adt

- In each `core/<dir>/types.ts`, delete the local `IXResults` and import it from interfaces-adt.
  Do the same for `IServiceBindingPublicationConfig`.
- Every `xDocuments` keeps `satisfies IXResults` and no annotation.
- Remove these names from adt-clients' public exports.
- In `packages/adt-clients-legacy`, every file that imports one of the 30 client result-set
  contracts Part A moved (or `IServiceBindingPublicationConfig`) from `@mcp-abap-adt/adt-clients`
  imports it from `@mcp-abap-adt/interfaces-adt` instead — seventeen files, `clients/AdtClientLegacy.ts`
  and sixteen under `core/` — and the package's `@mcp-abap-adt/interfaces-adt` moves to `^20.2.0`. The six
  executor result contracts (`IClassExecutorResults`, `IClassTestRunnerResults`,
  `IFunctionGroupTestRunnerResults`, `IFunctionModuleTestRunnerResults`, `IProgramExecutorResults`,
  `IProgramTestRunnerResults`) stay in adt-clients and stay exported (spec §6).
- Verify: the root's `build`, `test:check` and unit suites pass, both packages.

### Task B3: the compositions go; each factory answers its class

- Delete `IClassContract<R>` and its 34 siblings from `AdtClient.ts`, with the doc block that names
  them.
- Each factory becomes one signature,
  `getX<R extends IXResults = typeof xDocuments>(results?: R): AdtX<R>`. The body and the default
  value stay as they are.
- `createAdtClient()` keeps answering `Promise<AdtClient>`.
- Type-level assertions (review focus 1): for one object of each slot kind (string slots, a
  `void` slot, the generic message-class set), `getX()` without a result set answers the same slot
  types as before.
- Verify: `build`, `test:check` and the unit suite of `packages/adt-clients` pass, with no test
  edited beyond its type imports. The legacy package does not compile until B3b; B3 and B3b are one
  commit series, pushed together.

### Task B3b: the legacy getters answer classes (`packages/adt-clients-legacy`, 0.2.0)

- `@mcp-abap-adt/adt-clients` moves to `^38.0.0`; the version goes to 0.2.0. (The result-set
  imports moved in B2.)
- The eleven getters with the base's two overloads each become one signature. Seven answer their
  legacy class (`getFunctionInclude`, `getInclude`, `getMessageClass`, `getLocalTestClass`,
  `getLocalTypes`, `getLocalDefinitions`, `getLocalMacros`). Four answer the base class
  through `absentOnLegacy` (`getTransformation`, `getScalarFunction`,
  `getScalarFunctionImplementation`, `getAppendStructure`). No composition is imported.
- A type-level test composes a contract from interfaces-adt alone and proves `AdtClientLegacy`
  satisfies it (review focus 2 and 4).
- Verify: the package's `build`, `test:check`, unit suite and `legacyClassesOnlyOverride.test.ts`
  pass.

### Task B4: the shape check reads the classes

- `manifest.ts` keeps `(client: AdtClient) => …`, so `ReturnType` is now the class.
- `factoryReturnsCoverClass.ts` drops its three composition imports and reads the factories'
  returns.
- Break one manifest claim on purpose and watch `test:check` refuse it, then restore
  (review focus 3).
- The runtime completeness test is unchanged and green.

### Task B5: the consumer-contract check

A type-level test under `src/__tests__/unit/` composes a contract from `@mcp-abap-adt/interfaces-adt`
alone: a few factories over result-set contracts, each answering a few atoms. It then proves:

- `AdtClient` and a hand-written object each satisfy it (the legacy half is Task B3b);
- an object missing one named member does not, with a `@ts-expect-error` (review focus 4).

### Task B6: docs and release notes

- README and `CLIENT_API_REFERENCE.md` describe what a factory answers (its class) and how a
  consumer composes the contract it needs.
- A 38.0.0 migration note covers:
  - the compositions are gone, so a consumer's contract is taken from interfaces-adt or composed
    from its contracts;
  - the result-set contracts are imported from interfaces-adt.
- The CHANGELOG gets a 38.0.0 entry.
- The legacy package's README and CHANGELOG get a 0.2.0 entry: the getters answer classes; a
  consumer composes its contract from interfaces-adt.
- Release order: adt-clients 38.0.0 is published first, then adt-clients-legacy 0.2.0.
- Commit, push, and run the Codex review.

## Part C: mcp-abap-adt (fr0ster/mcp-abap-adt, in its 21.0.0)

### Task C1: dependencies

`@mcp-abap-adt/interfaces-adt` moves to `^20.2.0` and `@mcp-abap-adt/adt-clients` to `^38.0.0`, both
from the registry. The lockfile is regenerated by npm and is checked to have no link. Fix any
compile error the adt-clients major causes before Task C2.

### Task C2: the server's client contract

- A new file in `src/lib/` (`adtClientContract.ts`) declares the contract the server accepts. It
  imports from `@mcp-abap-adt/interfaces-adt` only, and a source test pins that.
- It names only the factories the server calls. Start with none, type `createAdtClient()`'s
  answer against it, and add each factory and atom the compiler asks for. Each factory signature
  is generic over its result-set contract, like the library's, so `resultsFor(…)` sets flow
  through (review focus 5).

### Task C3: typed against it

- `src/lib/clients.ts`: the server's `createAdtClient()` and `getAdtClient()` answer the contract.
  `GuardedAdtClient extends AdtClient` stays, assigned to the contract.
- Change `resolveVersionedObject.ts`, the handlers that alias the client type, and the ~21 test
  fixtures to the contract.
- Verify: build, `test:check` and the full unit suite.

### Task C4: docs and release notes

- The server's CHANGELOG [Unreleased] major gets an entry for the client contract.
- Docs that name the client's type are updated.
- Open the PR and run the Codex review.
