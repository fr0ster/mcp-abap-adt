# Plan: one registry of ADT object type codes

**Goal:** [`2026-10-27-adt-type-codes-goal.md`](../2026-10-27-adt-type-codes-goal.md)
**Spec:** [`2026-10-27-adt-type-codes-design.md`](../specs/2026-10-27-adt-type-codes-design.md)

There are three repositories. Each gets its own PR, and this plan's documents live in #329. The order is fixed by the dependencies (spec §7):
1. the evidence is recorded first, in #329;
2. then interfaces-adt is published;
3. then adt-clients, adt-strategies and adt-clients-legacy;
4. then the server.

## Global constraints

- **Evidence.** A code is entered with its evidence or marked `unmeasured`. No code an answer shows to be wrong is entered.
- **No untyped codes.** No code is written as an untyped literal in production code. The scan checks this with the type checker.
- **No behaviour change for a correct code.**
- **Dependencies.**
  - Every dependency comes from the npm registry.
  - Workspace siblings in one repository may be linked until release.
  - Lockfiles are regenerated by npm.
  - Commands run as npm scripts, never `npx`.
- **Breakage.** Breakage is found by the compiler: `build`, `test:check` and each repository's CI steps.
- **Versions.** A major for each package whose types change; a minor for a 0.x package. A migration note goes with each.
- **Live runs.**
  - Live runs are on E19 (E77 only for 7.40 facts), as the test user only. The realm is checked first.
  - Any credential refusal stops everything.
  - A live run touches only our own objects. It never releases a request.
- **Committed answers.** A committed answer names no SAP system, system id, transport number or user name.
- **Owner-approved texts.** CLAUDE.md and SCOPE.md change only with the owner's approval of the text.

## Review focus

1. **A correct code still works everywhere.** Every request a recorded code sends today is unchanged. It is proven by the existing unit suites passing with only type edits, plus a live pass on E19 (Task S9).
2. **An unknown code from ADT is not lost.** An answer carrying a code outside the registry reaches the consumer as `unknownType`, at every place that parses codes (Task C6).
3. **What the model is offered works.** Each schema enum and description is built from its operation's subset, and every code in it is accepted end to end (Task S3, Task S9).
4. **The scan carries the rule.** It fails on an untyped code literal, a wrong code in a description and a wrong code in a comment. Each is proven by one deliberate break (Tasks C8, S6).
5. **The evidence test carries the rule.** It fails when a `recorded` entry has no answer in the corpus, and when the corpus carries a code the registry lacks. Each is proven by one deliberate break (Tasks C8, S6).
